# seo-structured-data-validation: specialist evaluation and negative controls

Domain `seo/structured-data`. This is a **proposed** evidence plan, never a real-system test result or execution permission.

## Specialist required inputs
Verify specialist prerequisites against real artifacts.

## Preserve skill-specific method
1. Identify supported Google Search feature and required/recommended properties using current feature-specific documentation; schema.org validity alone is not rich-result eligibility.
2. Inspect visible page content. Markup must accurately represent the page and entity; avoid hidden, fake, misleading or stale claims.
3. Prefer maintainable template-level JSON-LD when suitable; preserve correct entity identifiers and URL consistency. Do not invent ratings, prices or author credentials.
4. Validate syntax, required/recommended property constraints and current Google policies; distinguish Rich Results Test findings from general schema validators.

## Challenge / acceptance
- **Challenge:** Change canonical, robots, rendering or locale with a controlled URL set. Exercise an authorized contradictory, missing or adversarial test input.
- **Independent oracle:** Crawlability, indexability, structured data and measurable impressions are distinguished. Reconcile observed outcomes against a fixed control; do not use the generated answer as its own oracle.
- **Existing failure risks:** Unknown evidence remains UNKNOWN.
- **Stop/review:** No ranking, indexation or rich-result guarantee. Stop at incomplete authorizations, uncertain authoritative sources and irreversible changes.

## Acceptance evidence ledger
- [ ] Real source artifacts, version/effective date, scope, owner, permissions and lower-trust input boundary recorded.
- [ ] At least one baseline, negative control, ambiguity/near miss and recovery/retraction test documented with falsifiable expected outcomes.
- [ ] Domain-specific result, affected population, uncertainty, metrics and policy constraints independently verified.
- [ ] For implementation: isolated executable compatibility/failure tests, side effects and rollback. For advisory work: qualified independent review and citation audit instead.
- [ ] Simpler alternative, operational cost, incident/escalation owner and explicitly unresolved uncertainties stated.
- [ ] Separate proposed test from executed evidence; never claim production, legal, medical, security or regulatory certification from CI.
