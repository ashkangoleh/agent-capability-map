# game-design-prototype-plan: specialist evaluation and negative controls

Domain `gaming/core`. This is a **proposed** evidence plan, never a real-system test result or execution permission.

## Specialist required inputs
Verify specialist prerequisites against real artifacts.

## Preserve skill-specific method
1. Define target player and player motivation; separate fantasy, mechanic, progression and monetization assumptions.
2. Specify one measurable core loop with actions, rewards, feedback and fail states.
3. Choose a vertical slice that proves one risky hypothesis rather than a full production roadmap.
4. Describe mechanics, state machines, interaction systems, telemetry and balancing variables with explicit rules.

## Challenge / acceptance
- **Challenge:** Change frame-rate, client latency, save-state or economy input. Exercise an authorized contradictory, missing or adversarial test input.
- **Independent oracle:** Deterministic game-state and player experience metrics tested in representative builds. Reconcile observed outcomes against a fixed control; do not use the generated answer as its own oracle.
- **Existing failure risks:** Unknown evidence remains UNKNOWN.
- **Stop/review:** No quality/performance claim without build and playtest evidence. Stop at incomplete authorizations, uncertain authoritative sources and irreversible changes.

## Acceptance evidence ledger
- [ ] Real source artifacts, version/effective date, scope, owner, permissions and lower-trust input boundary recorded.
- [ ] At least one baseline, negative control, ambiguity/near miss and recovery/retraction test documented with falsifiable expected outcomes.
- [ ] Domain-specific result, affected population, uncertainty, metrics and policy constraints independently verified.
- [ ] For implementation: isolated executable compatibility/failure tests, side effects and rollback. For advisory work: qualified independent review and citation audit instead.
- [ ] Simpler alternative, operational cost, incident/escalation owner and explicitly unresolved uncertainties stated.
- [ ] Separate proposed test from executed evidence; never claim production, legal, medical, security or regulatory certification from CI.
